# WicHeic 1.1.31 ― Windows10 Explorer CPU負荷軽減・実機評価候補

## 要点

このバージョンの主目的は **HEIC初回サムネイル表示時のdllhost.exe（COM Surrogate）の高いCPU負荷を減らすこと**です。従来1.1.30の表示・回転・保存機能を維持しつつ、**4論理CPUのdllhost.exeで、6MP以上・8bit不透明HEICの最初の復号について、libde265 HEVCコーデックワーカー上限を4→2に変更**しました。Windowsフォト（Photos）経路は従来2ワーカーを維持。他ホスト、10/12bit、alpha、低画素数、並列2本目以降のポリシーも維持します。元の画像を変更する機能ではありません。

**まだWindows10ユーザー実機で確認できていないため、本書の「RC（実機評価候補）」を正式完成版と取り違えないでください。**

## Windows Server 2022 CIでの根拠

- [CPU負荷A/Bと同じRGB画素の検証 #41011035938](https://github.com/taku077/wic_heic/actions/runs/41011035938) SUCCESS：人工12MP HEIC、5回中央値。4ワーカーでプロセスCPU時間2140.625ms・経過616.639ms、2ワーカーでCPU1609.375ms・経過859.691ms。**CPU消費約24.8%減・処理時間約39.4%増**。CPU時間はGetProcessTimes（user + kernel）で測定。
- CI上の自動選択を確認：shell=1でworkers=2、photos=1でworkers=2、その他ホストでworkers=4。25サンプルで元画像・256px RGB完全一致、従来Photosの画素一致もPASS。
- [48タイル12MP研究 #41013602590](https://github.com/taku077/wic_heic/actions/runs/41013602590) SUCCESS：gridのタイル並列を減らす効果は**研究限定**。C++ラッパーの安全な実装方法がまだ確定していないため**このMSIにはタイル並列2/HEVC1の研究設定は取り込まない**。つまり複合grid/HDR実画像のCPU負荷が十分に下がるかは未確定。

## インストール前

1. Windows10 Pro 22H2 64bitを対象。現在使用中の旧1.1.30 MSI、または再入手可能な旧版を手元に残してください。
2. 開いているWindowsフォト・Explorerの作業を終了し、既存のHEICサムネイルのキャッシュ消去、他社コーデックの登録解除、既定の写真アプリ変更を実施しない。
3. 個人のHEIC原本は**一切編集しない**。確認する場合はExplorerで表示するだけ。回転保存の追加確認は必要なら**人工HEICだけ**を使用する。復元済みIMG_4074原本は使用禁止。
4. MSIが公開されたら、そのZIPに記載のSHA-256および同梱の人工HEICを照合する。ユーザーにはCI/ZIPのチェックサムと復元手順を提示する。

## 評価するポイント

- 以前の同じHEIC混在フォルダを開いたとき、タスクマネージャーの **COM Surrogate（dllhost.exe）** のCPU最大値だけでなく、CPU負荷が長く継続するか、他作業（Windowsフォト/Explorer）が固まるか。
- 初回サムネイルが遅すぎる場合は不採用。CPU使用率が少し低いだけで処理が極端に長くなる対策は成功と判定しない。
- 異常な回転、サムネイル消失、Photosの警告や回転保存の不具合が増えた場合は即座に前の版へ戻す。
- WPR再録画は現段階で不要。WIC/CPU診断ログは個人パスを含む可能性があるため提出前に確認。

## 復元

- 1.1.31を削除（設定→アプリ または既存のWindowsアンインストール手順）。
- 旧1.1.30 MSIを使用して再インストールし、Explorerを再起動する。実機の関連付けや他社COM登録を変更していた場合、正常復元を確認する。
- 1.1.31は以前のMSIを自動バックアップしない。作業前に旧MSIを確実に保存すること。

## リリースゲート

GitHub Actionsで **WIC x64ビルド、人工HEIC回転/色/保存テスト、CPUポリシー、製品MSI 1.1.31の版数、Windows runnerでMSIのインストール→WIC画素/保存テスト→アンインストール→WIC登録の元状態比較** の全てが成功し、同一テスト済みMSIをSHA-256とともに配布したときのみRCとする。失敗・未確認の場合は配布しない。

**意図的な保留項目**：本番Shell IThumbnailProviderへの置換、grid tile parallelism設定、他社Shell拡張の変更。速度よりCPU負荷が中心だが、安定性と原本保護を犠牲にしない。

## RC配布の構成

配布ZIPは、MSI本体・SHA-256/CI由来情報・本書・人工12MP HEIC（試験専用）で構成する。ユーザーの個人画像、WPR/ETL、実機ファイルのパスは一切含めない。**Windows10実機のCPU負荷改善値が未確定であることを隠さず、試験候補として扱う。**
