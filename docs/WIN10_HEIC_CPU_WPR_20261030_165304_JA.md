## 技術上の優先順位

1. 次期研究ビルドのWICイベントに、パスを記録しない `DecoderWorkerSelect` を追加し、4論理CPU・dllhost判定・選択worker数・同時復号数を追跡する。これで**2-worker制限が実際に選ばれているか**を既存軽量WICログだけで確認できる。ETLの再採取を先に要求しない。
2. libheifの独立タイルワーカーが既定4という点を重点調査。研究CIでは12MP 48タイル・`tile2+codec1`のプロセスCPU時間を約31～35%減らしたが、自作WICはC++ `heif::Context` を使うためC API setterを直接呼べない。危険なprivateメンバー操作はしない。移行の実装/回帰を検証するまでは未実装扱い。
3. 「CPU負荷最大値」「40%以上の時間割合」「CPU総時間」「Photos応答/Explorerサムネイル速度」を独立指標として評価する。ピークだけ下げ、処理時間だけ増やす対策は不採用。
4. 実機の原本は上書きしない。IMG_4074は再利用禁止。追加の大容量WPR/ETLを繰り返し要求せず、検証可能なコード修正から進める。1.1.32候補を出すのは意味のある安全なCPU削減とCI完走の区切りだけ。
