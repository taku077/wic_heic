## 1. この期限の意味
期限までに**インストール可能なx64 MSI候補、SHA-256、対応内容・未対応内容、簡単な導入前確認/復元手順、CIへのリンク**を揃え、提出可能な状態にする。新たなバグの発見や小改善を理由として無制限に期限を延長しない。

「MSI候補を作って渡す」ことと「実ユーザーのWindows 10フォトで完成を確認した」ことは異なる。未検証なら `Win10-Photos-UNVERIFIED` と表示し、完成版・実機動作保証をうたわない。候補の提出がユーザーPCへの導入同意を意味するものではない。現行環境の復元可否が確定するまで、ユーザーに導入を促さない。

## 2. リリース対象（最低限）
1. 旧WicHeic Repair Test v1.1.18系列を起点とし、同版で確認されていたHEVC警告なし/フォト編集・回転UIを回帰させない（CIがUIを検証したという意味ではない）。
2. **Exifを含む人工HEICを90°回転し、元データ保護と幾何学的な正しさが成立するWIC保存経路**を維持。WICの元フレーム直接入力、および全画像WICRect経由を対象とする。
3. 既存のExif向き正規化、ICC保持、原本保護、WriteSourceの安全拒否・サイズ検査・Commitの一貫性を維持。
4. MSIのx64ビルド、人工HEICを用いたWIC試験、CI隔離環境のMSI導入/削除、COM登録状態復元を成功させる。
5. 出自不明の変換済みWICラスタを「元HEVC」と決めつけてメタデータ回転だけ行うことは禁止。

## 3. 今回は対象外とする項目（未来の課題）
- すべてのHEIC派生形式、HDR/ゲインマップ/埋込サムネイル、複雑なマルチフレームの完璧な無再圧縮回転
- あらゆる再圧縮編集でExif/XMP/MakerNote/ICC/10/12bitを無条件に保持すること
- 新規高速化、GPU対応、新たなWICアーキテクチャ、HEIC Manager改修
- 根拠のない全件網羅テストや新たな研究テーマ
必要な場合は「非対応」と明示するか安全に拒否し、元画像・既存ファイルを破壊しない。未対応が存在すること自体を期限延期の理由にしない。

## 5. 合否判定を増殖させない
対象CIを原則以下の**4群に固定**する。
A. Visual Studio x64 ReleaseでDLL/MSIがビルドできる
B. 既存の人工Exif HEIC 90°回転保存→ファイル再読込→寸法/Exif向き/画素一致/全データ一致（既存CI）
C. 従来の直接無圧縮WICコピーと人工ICC付きラスタ回転の既存回帰（既存CI）
D. 隔離Windows CIでMSIインストール→WIC処理→アンインストール→登録状態復元（既存CI）
これ以外の調査・試験は、実害と再現経路が明確で、当該リリースを停止する故障に直結する場合に限定する。

## 6. バイナリー提供と安全な復元
- 現在のCI workflow `.github/workflows/repair-x64-build.yml` は主ブランチでMSIアーティファクトのアップロードを**明示的にskip**する。この障害を取り除き、成功したビルドと復元確認後に一度だけリリース候補をアップロードできるようにする。
- 公開名は `WicHeic-118-x64-Win10-Photos-UNVERIFIED-RC` 等、Windows 10フォトの実機未確認を明記する。
- 旧1.1.18を正常版扱いしない。旧版でも回転変形/保存失敗/サムネイル角度不一致が存在した。
- ユーザーの現行WIC登録と DLL ハッシュ、元へ戻せる旧MSI/復元手順の**実機向け確認がなければ導入を勧めない**。CI Windows Server 2022の復元成功はユーザーWindows 10の復旧証明ではない。
- 実機試験は本人の明示的同意後、完全に独立した空フォルダの**人工HEIC**のみ。IMG_4074など実写真は利用しない。HEIC Managerには触れない。原本自動削除・上書き禁止。Explorer停止事故のリスク管理を外さない。
