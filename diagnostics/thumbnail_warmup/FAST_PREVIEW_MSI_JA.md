# WicHeic Fast Thumbnail Preview v0.4.0 — 適応型HEVCデコード（Windows 10 x64 実機評価版）

## v0.3.0からの変更
6MP以上の**通常の8bit・アルファなしHEIC**をサムネイル生成するとき、同じCOMサーバープロセス内でデコード中の対象が1枚だけなら最大4スレッド、複数枚同時なら2スレッドに切り替える。論理CPUが4未満なら最大2スレッド。小画像、10/12/16bit（HDR）、アルファ付きHEICには適用しない。

ユーザーPCに既存のWICデコーダーを導入する必要はない。専用のHEICデコーダーはMSIに同梱し、Windows全体には登録しない。「フォト」の回転保存には関与しない。元HEICは変更・削除・再エンコードしない。

## 先行するCI実験（Windows Server 2022、人工12MPの同一画像）
| 設定 | 1枚の画素取得中央値 | 4枚同時の完了時間 |
|:---|---:|---:|
| 2スレッド（v0.3.0） | 417.86 ms | 1019.05 ms |
| 3スレッド | 342.23 ms | 1031.55 ms |
| 4スレッド | 283.39 ms | 1022.14 ms |

ログ：https://github.com/taku077/wic_heic/actions/runs/39577291372
全条件で出力画素のハッシュが一致した。各条件2回のみで、ユーザーのWindows 10、i5第7世代、実写HEICでの同じ速度向上は**未確認**。4スレッドは1枚処理時にCPU負荷が増えるため、複数同時の際は2に抑える方式を試験中。別のCOMプロセス同士にはこの制御が効かない場合がある。

## Windows 10での更新
1. **v0.3.0を事前アンインストールせず**に、このZIP内の `WicHeicFastPreview.msi` を実行する。
2. 完了したらWindowsを再起動する。
3. 元写真ではなく同じHEIC写真のコピー10〜30枚を新しいフォルダに置き、同じアイコンサイズで初回サムネイル表示時間とCPUの体感を比較する。
4. 向き、色、画質、表示失敗、異常終了がないかも確認する。回転保存は試さない。
5. インストール失敗時には警告画面を報告し、レジストリ削除やHEIC Managerアンインストールを実行しない。

## 安全な配布の前提
隔離GitHub Actionsで、実際の `.heic` Shellサムネイル生成、キャッシュ再利用、人工画像のSHA-256維持、インストール・削除の復元、およびv0.3.0からのMSI更新・完全アンインストールに成功した場合のみ、利用者向けリンクを案内する。
