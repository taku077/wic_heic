# Windows Shellサムネイルキャッシュの低負荷先読み

## 設計
- WinThumbsPreloader方式の\`IThumbnailCache\`を利用する。Windows Shellが所有するキャッシュだけに生成結果を保存し、独自の二重画像キャッシュは作らない。
- \`wictest/ShellThumbnailWarmup.h\` は**WIC DLL本体へリンクしない**独立ヘルパー。常駐、Shell登録、関連付け変更なし。
- 同じWindows Shellセッション内で\`WTS_INCACHEONLY\`をまず照会。未キャッシュの画像だけ\`WTS_EXTRACT\`で生成し、既存キャッシュの再生成を避ける。
- フォルダ列挙は**HEIC/HEIFのみ、直下のみ、最大30ファイル、ジャンクション/シンボリックリンクはたどらない**。ユーザーが明示的に選択したフォルダ以外は処理しない。
- ワーカー数は上限2。COMは各スレッドで初期化して使い、バックグラウンド優先度で通常PC操作を妨げにくい設計。途中中止用フラグを用意。
- 既存のHEIC/JPEGファイルには読み出しのみで、ファイル変更・メタデータ変更・原本削除はしない。
- 自動試験は人工HEICを10枚ずつ複製し、最初の未キャッシュ状態と生成後のキャッシュヒット件数、生成所要時間、再訪の照会時間を確認する。

## 検証と留保
GitHubのWindows Server 2022 CIは\`IThumbnailCache\`の基本動作を確認するもの。Windows 10 Explorerの「未キャッシュ初回表示」や多数ファイルの体感速度の代替にはならない。並列数は1/2で比較し、実測で改善がなければ並列化は有効にしない。

> JPEG同等の最終条件は別途維持。サムネイル先読み成功だけでは、10bit/EXIF/ICC/HDR/無再圧縮回転の完成を意味しない。
